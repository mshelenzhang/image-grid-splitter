# Image Grid Splitter ✂️
**English · [中文](./README.zh-CN.md)**

**A privacy-first browser tool for splitting composite images into clean, reusable panels.**

Built from a real content-production need and developed through an AI-assisted product workflow.

> **Public product showcase.** The production source code and implementation details are maintained privately.

---

## ✨ What It Does

Image Grid Splitter turns composite images into separate, ready-to-use image files directly in the browser.

It is designed for workflows where multiple visual panels are generated or combined into one image and need to be separated quickly for publishing, editing, or reuse.

### Key Features

- 🔍 Automatic layout detection
- ↔️ Adjustable split lines for manual fine-tuning
- 🖼️ 2-panel and 4-panel layouts
- 🧩 Mixed horizontal and vertical layouts
- ⬜ Intelligent whitespace handling
- 🏷️ Batch naming by sequence or topic
- 📥 Individual image downloads
- 📦 Batch download
- 🔒 Browser-local image processing

Images are processed locally in the browser and are not uploaded to an external image-processing server.

---

## 🖥️ Product Preview

The interface follows a simple workflow:

**Upload & Detect → Adjust & Name → Download**

The product provides visual split previews before export, allowing detected boundaries to be checked and adjusted before the final images are generated.

## 💡 Why I Built It

The project started from a recurring problem in my own content workflow.

Composite images were useful for generating and organizing visual content, but manually separating them into individual assets created unnecessary repetitive work.

Instead of repeatedly solving the same task by hand, I turned the workflow into a small product.

The project evolved from a local utility into a browser-based tool with automatic detection, interactive adjustment, batch naming, export controls, and privacy-first local processing.

## 🛠️ Product Architecture

The current working version uses:

**HTML5 · CSS3 · Vanilla JavaScript · Canvas API · File API**

The product is intentionally lightweight:

- No application framework
- No database
- No external image-processing API
- No API keys required
- No image upload required for processing

This architecture keeps the tool fast, portable, and privacy-conscious.
